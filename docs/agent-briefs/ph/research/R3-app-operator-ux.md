## A. What the app shows today, and what is wrong with it

- **Flow [SEEN].** Mock sign-in (5 equal oxblood buttons, `…/2026-10-08-ph/01-launch.png`) → Patients → Programs tab (patient picker) → builder → "Send to headset" (assign_program) → Monitor tab → card → Reports tab → report. Start also exists in Devices ⋮ (`features/devices/devices_screen.dart:201-244`). Status arrives every 500 ms (`game/Assets/Shell/Runtime/OpusSessionRunner.cs:256`), traces in 10-sample chunks.
- **Card [SEEN]** `features/live/phantom_live_screen.dart` (831 lines): AppBar (title, "Demo"/"Headset offline" tag, observer toggle :177-192) → Status (phase name, SYNC/ASYNC chip, time left, 2 node chips :386-560) → Controls (7 buttons + order selector :711-801) → Live signals (two 96 dp plots + legend :566-677). <900 dp: status, controls, signals; ≥900 dp: 420 dp left column, traces right (:282-348). Observer: no AppBar/controls, phase 40 sp, chip 56 sp, time 72 sp (:399-411). No overflow or clipping in the 393 dp shots `02`-`05`; the A1 tests assert none at 360/390 with 2.0x text (A1 log).
- **Report/lists [SEEN].** Reports = patient, date, success % (`features/sessions/reports_list_screen.dart:152-179`); report = Orchard sections only (`features/sessions/session_report_screen.dart:145-211`); Devices = hub, headset rows, one "Haptic sleeve" row (`devices_screen.dart:188-299`).

Defects (D1-D3 can break the demo; paths as [SEEN] unless marked):
- **D1 Card unreachable when needed (real Quest; read in code, not observed on a Quest).** Monitor mounts the card only while a connection has `activeSessionId` (`features/live/monitor_home_screen.dart:52-62`, `core/providers/hub_providers.dart:224-231`). The id comes only from the envelope `session_id` and is cleared on idle/finished/error (`core/hub/hub_connection.dart:170-172`). The runner creates the id at Start (`OpusSessionRunner.cs:327,364`; `game/Packages/com.opus.sdk/Runtime/Transport/LiveClient.cs:153,174`; null ids are not serialised, same folder `LiveMessage.cs:23`) and sends `finished` at the end (`OpusSessionRunner.cs:399,517-523`). So before the first Start and after every run the Monitor tab says "No headset connected" (`monitor_home_screen.dart:101`) with no Start / Next person. `sim/live/fake_headset.py:599-609` assigns an id up front, which is why the mock demo and tests never showed it.
- **D2 Ownership scale mismatch (cross-track).** Unity records q1-q5 as -3..+3 (`game/Assets/Games/PhantomHand/Runtime/Questionnaire.cs:25`, emitted `PhantomHandModule.cs:249`); the event schema demands integer 1..7 (`contracts/schemas/event.schema.json:115`); analytics averages raw values and labels them `likert_1_7` (`analytics/opus_analytics/metrics/embodiment.py:322-338`); the headset witness bar assumes -3..+3 (`WitnessSummary.cs:80` beside `Questionnaire.cs`, and `Ui/WitnessView.cs:104`); every fixture uses 1..7. A real run gives events that fail the contract and a negative "likert_1_7" ownership. Neither report nor mirror may trust the unit string until Opus settles it (X1).
- **D3 No Phantom Hand report.** `SessionMetrics` has no `embodiment` field (`data/models/metrics.dart:60-70`; "embodiment" has 0 hits in `app/lib` and `app/test`). A PH `metrics.json` has `trials: []` (`contracts/fixtures/sessions/phantom_hand_min/metrics.json`) so the report reads Trials 0, Success 0 %, empty donut/bars (`session_report_screen.dart:145-211`); the no-metrics fallback builds Orchard reaction times (:82-104). "Run analysis" shells out to a desktop Python venv (`core/providers/hub_providers.dart:264-285`) - on the Android phone it cannot work (inference: no analytics venv there).
- **D4 Reports list cannot tell participants apart.** Row = name + date, success "-" (`reports_list_screen.dart:152-179`); the headset's default patient is `synthetic-longitudinal-9000` = "Priya Nair" (`OpusSessionRunner.cs:50`, `app/assets/fixtures/patients.json`), so every run is the same name on the same day; sessions whose `patient_ref` is not in that mock list are never listed (:202-232).
- **D5 No link health on the card.** AppBar shows only "Demo" or a red "Headset offline" (`phantom_live_screen.dart:177-192`); no RTT (the Orchard monitor shows it, `live_monitor_screen.dart:57-62`) and no "last update" age: snapshot has no timestamp and `connected` flips only on socket close (`data/repositories/hub/hub_phantom_live_repository.dart:24,32-35,65-77`). After a Wi-Fi stall (3 missed 1 s pongs, `core/hub/hub_connection.dart:49-53,252-261`) countdown and traces freeze while looking live.
- **D6 Traces cannot prove the flinch.** y-axis auto-scales per 10 s window with no scale, baseline or unit (`features/live/phantom_trace_plot.dart:109-130`; window `data/models/phantom_live.dart:165`); the spike scrolls off after 10 s; axis words and "m/s²" hard-coded (`phantom_live_screen.dart:631-632,668`); height fixed 96 dp (:578) so at 1280x800 over half the right pane is empty (`app/test/phantom/goldens/phantom_card_tablet_dark_1.0x.png`). The python fallback already draws "baseline 420", y labels and named markers (`logs/sessions/screens/ph/s2/live_plot_sync_threat.png`).
- **D7 Raw id and dead slab before Start.** Unity sends phase `idle` (`game/Assets/Games/PhantomHand/Runtime/PhaseStateMachine.cs:32`); `phantomPhaseLabel` has no `idle` case so the card prints "idle" (`phantom_live_screen.dart:231-246`); a 28 sp "No condition" chip fills prime space before induction (:457; `02-live-card-idle.png`).
- **D8 Clutter, no "one next action".** 7 buttons always visible + order selector (:775-792); disabled ones give no reason; Start is always styled primary even when disabled, End is the only filled red button while running (`phantom_card_desktop_dark_1.0x.png`); "Abort phase" has no confirm (:124-139); every "Confirmed" label stays forever (`03-live-card-running.png`); selected order segment is almost invisible (`04-live-card-traces.png`, `showSelectedIcon:false` :783). v3 asks one primary action per screen (`docs/design/OPUS_DESIGN_V2.md` §4).
- **D9 No sequence context.** Only the current phase and its own countdown (:386-437): no "step n of N", no next step, no total time; `game_state` has none of these (`contracts/LIVE_PROTOCOL.md`). Phase order is derivable from `conditionOrder` (default async_first, `phantom_live.dart:358`).
- **D10 Chrome eats the phone.** Avatar strip 44 dp + a second status-bar inset (likely nested SafeArea: `core/a11y/adaptive_shell.dart:112-131` + inner AppBar) + 64 dp bottom nav ≈ 180 of 852 dp; traces start below the fold and "Condition order" is cut by the nav (`02`, `04` png). Observer hides only the AppBar: strip and nav stay (`05-observer.png`). A dashboard should fit one screen [EVIDENCE S6].
- **D11 Light theme by default and colours fail on it.** `core/providers/settings_providers.dart:17` = `ThemeMode.system`. Contrast computed here on #FFFFFF: info 2.89, accent2 2.82, good 2.29, warn 2.20, teal 2.11 (graphics need 3:1, text 4.5:1; on the dark panel all ≥ 5.65). - **D12 Devices says "Haptic sleeve not connected" for a PH headset.** It reads `status['haptic']` (`devices_screen.dart:190`, `shared/metrics/haptic_status.dart:68`) but PH status carries nodes only in `game_state.nodes` (`game/Assets/Shell/Runtime/PhantomHandSceneController.cs:540-558`); no bio row, no power-bank-only note (APP.md A2 item 4); subtitle joins with " · " (`devices_screen.dart:200`), which v2 §3 forbids.
- **D13 Link loss swaps the card for fake Orchard data** when opened from a patient's "Live now": the provider returns null without a connection (`live/phantom_live_providers.dart:31-35`) and `LiveMonitorScreen` falls back to the mock Orchard stream (`live_monitor_screen.dart:38-43,528-540`). Not on the Monitor-tab path (empty state there).
- **D14 Screen can sleep mid-run.** No wakelock in `app/pubspec.yaml` or `app/lib` (grep 0); a watched-but-untouched phone dims (inference: device timeout).
- **D15 Builder detour.** Opens on the first manifest (`features/programs/program_builder_screen.dart:94`), shows rehab "Schedule" (:145), enum options still raw "sync_first" (A1c log), only a snackbar after Send (:237-241); bottom nav highlights Patients on `/programs/new` (`adaptive_shell.dart:39-44`; A1b log).
- **D16 Same condition, two colours.** Headset witness cards: In sync = Good green, Delayed = Warn amber (`game/Assets/Games/PhantomHand/Runtime/Presentation/Ui/PhWitnessPanel.cs:43-44`); app card: info blue / warn amber (`phantom_live_screen.dart:255-259`). Green vs amber have a luminance ratio of 1.04 (computed): no lightness cue for red-green colour blindness; blue vs amber is the safer pair [EVIDENCE S1].
- **D17 Smaller.** Node chips say only "Offline" (no cause, fix, battery) and `status.hands`/`fps` are ignored (`phantom_live_screen.dart:477-560`, `OpusSessionRunner.cs:538`); Hindi is machine text (A1c log; the golden tofu is the test font only) and SYNC/ASYNC stay Latin while the headset says साथ-साथ / देरी से (`game/.../Ui/PhStrings.cs:37-38`).

## B. Ranked backlog (S ≤ 1 h, M ≤ 3 h, L > 3 h; Imp = demo impact 1-5; PNG = existing golden PNGs it would invalidate)

Order: quick wins, then M by impact, then L. Totals: 99 PNG exist (72 in `app/test/goldens/goldens` = 6 screens x 12, 21 in `app/test/phantom/goldens` = 13 card + 8 observer, 6 in `app/test/reach_trace/goldens`).

**What comparable dashboards do (research → decision).** Where no source settles a point it says [OPINION].
- *Current step in a fixed sequence.* VR proctor dashboards put viewpoint, gaze and current step on one panel [EVIDENCE S9]; progress guidance prefers percent-done once a step takes ≥ 10 s [EVIDENCE S6]. → run rail with ✓ ● ○ and a thin bar per phase (B9); phases here last 5-90 s.
- *Time remaining.* m:ss plus a filling bar, not a spinner [EVIDENCE S6]. m:ss exists; the bar is new (B9). No total-run clock until the headset sends one (X3); until then say "about".
- *Two contrasting conditions.* Blue/orange pair, labels on the graph instead of a legend, solid vs dashed or filled vs hollow, never colour alone [EVIDENCE S1, S2]. F1 timing colours work only because viewers learn them and the sheet is kept light [EVIDENCE S10]. → one pair on every PH screen (X4); chips always carry words.
- *Live traces with events.* A vertical line + icon per event with a label [EVIDENCE S8]; biofeedback tools draw a target/threshold line the clinician can set [EVIDENCE S7]. → baseline line + "× resting" readout and labelled impact/burst (B8, B10). Fixed scale with the gain shown beats silent auto-scale [OPINION; no study found]. A sweep (overwrite) display may be easier to glance at than a scrolling one [EVIDENCE S8, weak: one commentary]; optional for B8.
- *Connection health.* VR booth tools show per-station state and time left in one row [EVIDENCE S9]. → one pill with RTT and the age of the last update (B12) [OPINION on wording].
- *One next action.* [OPINION] A run is a script, so at most one press is the likely next one; the rest wait behind ⋯ (B13); confirm only the irreversible ones.
- *Mobile at about 390 dp.* Compact width < 600 dp, targets ≥ 48 dp [EVIDENCE S5]. Grips: 49 % one hand, 36 % cradled, 15 % two hands, changing within seconds, and the author later said people touch the screen centre most [EVIDENCE S5], so no fixed "thumb zone": primary action low and central, destructive ones away from the top corners [OPINION]. A dashboard fits one screen [EVIDENCE S6] → hide the nav during a run (B14).
- *Lay audience, ten seconds.* Dot/dumbbell rows on common scales are read most accurately [EVIDENCE S3]; plain visual aids help across numeracy levels [EVIDENCE S4]; broadcast designers use a 3-second digestibility test [EVIDENCE S10]. → four rows + one flat pointer, big values, the gap as a signed number (C). No study compares dumbbell vs slope for lay readers; try both on three colleagues [OPINION].
- *Audience view in VR demos.* Observers get a third-person or mirrored state; first-person only to troubleshoot [EVIDENCE S9]. → we mirror state (phase, traces, witness cards), not headset video (D).

**Wording [OPINION].**
- Names: "In sync" / "Delayed" (headset words); SYNC/ASYNC only small on the operator card.
- Verdict, one generated line: "In sync, the hand felt more like yours (5.5 vs 2.5) and your sense of where it was moved 2.0 cm toward the virtual hand." / "No clear difference between in sync and delayed this time." / "Mixed: …".
- A gap counts only when ≥ 0.5 cm drift, ≥ 1 point ownership, ≥ 25 % flinch size or latency (one constants block, easy to tune). Say "this time", never "significant" or "proves": n = 1. The real L3 fixture shows flinch size equal in both conditions (6.0x vs 6.0x, `tools/demo/tests/fixtures/ph_l3_main/metrics.json`), so "no clear difference" must be a normal outcome, not an error.
- Delta chip = In sync minus Delayed with unit ("+3.0", "-40 ms"), neutral colour (green/red mean good/bad in v3; "higher" is not "good"). Round: ms to 10, others 1 dp.

**Quality flags (ok / degraded / missing; `invalid` is in the schema too).**
- `ok`: plain row. `degraded`: hatched-ring dot, word "Partial" + glyph ◐ at the row end, tap shows the reasons, delta chip prefixed "~", left out of the verdict. `missing`: no dot, dashed empty track, word "No data" + glyph ∅ + short reason. `invalid`: as missing, "Not usable", `bad` colour allowed.
- Condition-level line above the rows when ≥ 2 touch-dependent values of one condition carry `touch_incomplete` / `cues_undelivered` (as in `ph_l3_fault_node_a_off`): "The sleeve missed touches during In sync. Read those numbers with care." When the muscle sensor was off, the two EMG rows show "No data" and the IMU values stand in (`ph_l3_fault_node_b_absent`).
- Never colour only [EVIDENCE S1, S2]; amber is reserved for Delayed, so flags use `slate` text + glyph, not amber.
- Reasons → words (from the fixtures `tools/demo/tests/fixtures/*/metrics.json` and `analytics/opus_analytics/metrics/embodiment.py:283,317,322-338`): `node_absent_bio` "Muscle sensor was off"; `touch_incomplete` "Some touches were not felt"; `cues_undelivered`, `few_delivered_strokes_*` "Sleeve missed touches"; `no_samples_in_window` "No reading around the stone"; `no_withdrawal_detected` "No hand movement seen"; `shared_pre_probe` "Same starting point used for both"; `sync_value_missing` / `async_value_missing` "One side has no number"; `only_one_of_q1_q2`, `*_absent` "Question not answered"; `probe_unconfirmed` "Pointing check not confirmed".
