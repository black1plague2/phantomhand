# End-to-end testing — levels, gates, KPIs (7–9 Oct)

Nothing is "done" until its level passes here with real output in a log. Gates G1–G3 are PRD §14's gates.

## Levels

| Level | Name | What runs | Who | When |
|---|---|---|---|---|
| L0 | Unit | each track's suite | builder | every run |
| L1 | Contract | `contracts/validate.py` + fixtures + every produced session | builder, Opus | every run |
| L2 | Component vs fakes | Unity vs `fake_hub` + twin-lite; firmware compile + bench self-test; app vs mock/fake_headset; analytics vs fixtures | builder | every run |
| L3 | **Pipeline in sim** | Unity batch PlayMode + hub + twin-lite (A+B) + analytics, at once (`run_pipeline.py --game phantom_hand --sim`) | ph-e2e | Oct 8 evening, before L4 |
| L4 | Hardware in loop | Unity on Quest Link (or APK) + real Node A/B on the power bank + laptop hub | humans + ph-e2e | Oct 8 night |
| L5 | Demo on device | APK on Quest 3 standalone + nodes + hub; demo_mode and full run | humans | Oct 9 |

## Gates

**G1 (Oct 7 night) — bench + foundations**
- Both nodes flashed, discovered over Wi-Fi by `tools/demo/live_plot.py` (or the twin viewer), no USB tether.
- Node A: I2C scan 0x68 + 0x3C; both motors pulse via the self-test; OLED shows id + IP.
- Node B: forearm squeeze ≥ 3× baseline on the envelope at 3.3 V; noted again with a motor buzzing nearby.
- `motor_soa_ms` chosen on the bench (A then B feels like one stroke); spin-up measured.
- U1 EditMode green; contracts v0.2 green; regression floor from O0 intact.

**G2 (Oct 8 night) — one full run end to end (PRD §14)**
L3 table, all must pass:
| Check | Threshold |
|---|---|
| Phases in order, both conditions | 100 % |
| Stroke cues acked by the twin | ≥ 98 % |
| SYNC visual-to-send timing error (timing_err_ms) | mean ≤ 20 ms, p95 ≤ 40 ms |
| ASYNC delay | 500–700 ms on ≥ 95 % of strokes |
| Live status RTT to hub | p50 < 250 ms; invalid messages 0 |
| Session valid (`validate.py --session`) and uploaded to the hub | yes |
| Analytics runs and writes `embodiment` with quality flags | yes |
| Faults: Node A off at 50 %, Node B absent, hub absent 30 s | run completes; "Sleeve offline" shown; flags set; upload retried |
Then L4 with real nodes:
| Check | Threshold |
|---|---|
| Both nodes discovered + streaming wirelessly | yes |
| Cue send→ack p95 | < 100 ms |
| Touch-to-sight in SYNC (timing_err + ack/2 + spin-up) | < 100 ms (PRD KPI) |
| EMG flinch on the live trace after the threat | clearly above baseline (≥ 3×) |
| Motor artefact on EMG with motors running | measured, logged, gated by analytics |
| Hand tracking confidence High with the sleeve on | ≥ 90 % of frames |
| Power bank stays on with both boards for 30 min | yes |
| One full 4-minute run recorded end to end | yes |

**G3 (Oct 9) — demo-ready (PRD §12)**
| Check | Threshold |
|---|---|
| demo_mode run twice in a row, no reset, APK on Quest 3 | yes |
| 72 Hz held (frame drops < 1 %, OVR Metrics Tool) | yes |
| Reset to calibrate between people | < 10 s |
| 5-teammate pilot: SYNC > ASYNC for drift and flinch (direction), ownership higher in SYNC | ≥ 4 of 5 |
| Witness screen shows both conditions' numbers | yes |
| Live dashboard (Flutter card or laptop plot) shows EMG + accel during the run | yes |
| Runbook (H4) followed by someone who didn't build it | yes |

Note on the pilot row (research R4, 8 Oct; the PRD §12 threshold is unchanged until the team decides): with five
people the drift direction alone would pass only 34–53 % of the time even if the effect is real (binomial, ≥ 4 of
5, assuming each person has a 60–70 % chance of the right sign; that assumption is R4's). Report every
channel as "X of 5" whatever it is, never tune parameters to pass this row, and lead the demo with the rating and
the flinch. Proposed wording for the team: "rating higher in SYNC in ≥ 4 of 5 and a flinch visible on the trace".

## Defect flow

ph-e2e lists each failure: level, check, observed vs expected, repro command, suspected track. Opus turns each
into a REDO. After freeze (Oct 9 12:00) only defects on the demo path are fixed; the rest go into the log as
known limitations for the pitch.
