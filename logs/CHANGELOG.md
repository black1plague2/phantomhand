  `firmware/opus_sleeve/opus_sleeve.ino` v0.3.0 and both haptic schemas. New structure: status-at-a-glance →
  protocol → **open conflicts** → guarantees → parts → circuit → pipeline → tests → 4-motor verdict → deferred
  battery → answers owed. Found three real contradictions: the draft's `pattern` list drops `buzz` (the success

  until after the prototype demo. Firmware may implement 0-3 defensively; software keeps `enum: [0,1]` and never
  sends `motor` > 1 until Opus lands schema + HapticClient + Flutter UI + fake_haptic as one change set.
