## CHECKPOINT 1 — item 1: the hanging test, root-caused and fixed

Root cause (confirmed by bisecting with temporary `print()`s, since removed):
**`testWidgets` runs its entire test body inside flutter_test's FakeAsync
zone**, not just the `pump()` calls. A bare `dart:io` read
(`DirectorySessionsRepository.open`, called before any `pumpWidget`) never
completes under FakeAsync — its completion arrives via
`_RawReceivePort._handleMessage` (the IO helper isolate's port callback,
exactly what the original `TimeoutException`'s stack trace showed), and
FakeAsync doesn't process that kind of real event. `tester.runAsync()` is
the one mechanism that unpauses the real event loop long enough for it to
fire. run12's attempted fix wrapped `pumpWidget` itself inside `runAsync`
(wrong direction — pump/pumpWidget must stay in the normal fake zone) and
also left the *first* `.open()` call, before that block, totally unwrapped —
so it still hung, just for a shorter, bounded 60s instead of the suite's old
10-minute default.

Fix applied: wrap only the two things that need the real event loop —
(a) the initial `.open()` call and (b) the settle waits after
`pumpWidget` — in separate `tester.runAsync()` calls, with `pumpWidget`/
`pump()` themselves called normally (outside `runAsync`). The settle step
polls (`for round in 0..15: runAsync(delay 100ms); pump(100ms); break if
found`) instead of a fixed count, since the screen watches several chained
FutureProviders (metrics → events/traces/envelope) that don't all start
their own IO on the same pump.
