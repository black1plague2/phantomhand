**`OrchardReach.Tests.Editor`** (30 tests): first run (`runId b135fc9e`) — 2 distinct failures (both in
`OrchardReachModuleTests`, a real production bug in `OrchardReachModule.cs`, not a test bug this time):
- `FullBlock_RunsAllTrialsAndEmitsWellFormedEvents`: "all 5 trials should have run, Expected: 5, But was: 6"
- `Timeout_WhenHandNeverMoves_StillAdvancesTrials` (fails one line later, at the `trial_end`/timeout count assert):
  expected 2 timeout events, got 1.

**Root cause:** `OrchardReachModule.TrialsCompleted` was `_trialIndex + 1`, but `_trialIndex` is `StartNextTrial`'s
internal "which slot am I setting up" counter — it gets incremented one extra time at the very end (the sentinel
call that discovers `_trialIndex >= TrialCount` and calls `End()` without starting a trial), so at block-end
`TrialsCompleted` read `TrialCount + 1` (test 1's "was: 6" for `TrialCount=5`). Worse, mid-run it *undercounted in
effect for any caller polling it as a "some N trials done" signal*: because `StartNextTrial` runs synchronously
inside `OnTrialFinished`, `_trialIndex` (and thus the old `TrialsCompleted`) flips to reflect the *next* trial
the instant it **starts**, not when the *current* one **finishes**. Test 2 polls `module.TrialsCompleted < 2` as
its "keep ticking" loop condition expecting it to reach 2 only once the second trial's own timeout fires — but the
old formula hit 2 the moment the second trial started, so the loop exited early and the second trial's timeout
never got a chance to fire, leaving only 1 timeout event instead of 2.

**Fix** (`game/Assets/Games/OrchardReach/Runtime/OrchardReachModule.cs`): added a dedicated
`_trialsCompletedCount` field, incremented exactly once per `OnTrialFinished` call (i.e. once per trial that
actually ended, whatever the outcome), reset to 0 in `Configure()`. `TrialsCompleted` now returns that field
instead of deriving from `_trialIndex`. Traced both failing tests by hand against the new logic before applying:
`TrialCount=5` case now ends at exactly 5 (the sentinel `StartNextTrial` call that triggers `End()` never calls
`OnTrialFinished`, so it doesn't bump the counter); `TrialCount=2` case now only reaches `TrialsCompleted==2` after
the second trial's `OnTrialFinished` actually runs, by which point both timeout events have already fired.
