## SPEC QUESTION (Opus reviews)
**Trace_20HzBins_AreAveragedAndAligned: 422.5 (test) vs 420.0 (code). Which side is right?**
- Input: EMG ramp `Series(0, 1000, 10, t => t)` = one sample every 10 ms (100 Hz), value = timestamp. Call at now = 1000 ms.
- `EndFor(1000) = floor((1000-100)/50)*50 = 900`; first call starts the cursor 500 ms back = 400; bins = floor((900-400)/50) = 10; `t0_ms` = 400 (the test already asserts this and `fs_hz` 20).
- Bin 0 = [400, 450): `i = floor((t - 400)/50) == 0` -> the samples at 400, 410, 420, 430, 440 (450 belongs to bin 1). Arithmetic mean = (400+410+420+430+440)/5 = **420.0**. That is exactly what the code returns.
- 422.5 is not the mean of any set of 100 Hz samples in that bin: it would be the mean of 10 samples at 5 ms spacing (400..445), i.e. a 200 Hz series; the test's own comment says "100 Hz EMG ramp ... mean of the samples at 400..440 ms". A continuous-time mean over the half-open bin would be 425.0, not 422.5 either.
- Spec: 03-SPEC D4 / LIVE_PROTOCOL.md v0.2 say only "down-sampled trace, fs_hz fixed at 20, newest samples since the previous status, t0_ms = session time of the first sample, EMG in raw ADC units". Nothing contradicts "average of the samples in each 50 ms bin, index i = t0 + 50*i" (the class doc of TraceDownsampler states exactly that, and the other 8 trace tests assume it).
- Decision: the TEST was wrong (arithmetic), not the code. Only the expected number (and its message) changed: 422.5 -> 420.0. If Opus intended a centred / inclusive-end bin, that would change the wire semantics (t0 alignment) and needs a contracts decision; nothing in the spec asks for it.
