## CHECKPOINT 1 — HUD-in-demo-mode bug fixed exactly as prescribed

Root cause (confirmed, same as CONTEXT.md ★★★ RUN 18 box): `OpusSessionRunner.cs` `Start()` returned at the
`!controller.UsingRealHands && !runWithDemoDriver` guard **before** reaching `OpusHud.Create(controller)`,
so any demo-driver run (no headset, `runWithDemoDriver` default false) got no HUD at all.

Fix in `game/Assets/Shell/Runtime/OpusSessionRunner.cs`:
- Added a `_driveSession` field = `controller.UsingRealHands || runWithDemoDriver`.
- `Start()`: `_hud = OpusHud.Create(controller);` now runs unconditionally, first, before any gating. The
  guard that used to `enabled = false; return;` now just does `if (!_driveSession) return;` **after** the
  HUD is created, skipping only the hub-client / session-lifecycle wiring below it (patientRef/deviceId
  setup, `StartClient`, `QueuePendingUploads`, the three event subscriptions).
- `Update()`: the whole hub-pump / phase-auto-advance / status-send block is now wrapped in
  `if (_driveSession) { ... }`; `_hud?.Render(...)` is the last line, unconditional, so a batch-test
  demo-driver scene (runWithDemoDriver still false) now shows the HUD too, it just never double-drives a
  session or a hub client.
- The component is no longer ever fully disabled (`enabled = false` removed from this path) since `Update`
  must keep running every frame to render the HUD; only the session-driving *behavior* inside `Update` is
  gated, per the brief's "keep only the hub/session half gated so batch tests don't double-drive."

Re-styled `game/Assets/Shell/Runtime/OpusHud.cs` to the brand palette (v2, same hex values as
`app/lib/core/theme/opus_tokens.dart` `OpusTokens.dark`), replacing every cyan-family color:
- Backdrop: v2 `panel` #120708 (was a blue-black `(0.04,0.07,0.09)`).
- New `AccentBar`: a thin oxblood (#7A1A20) strip across the top of the panel -- the "dark-red accent".
- Rule/stage banner text: v2 `crimson` #A8242C (was cyan `(0.55,0.95,0.85)`).
- Main body text: v2 `text` #ECE4E3 near-white (was flat `Color.white`).
- Progress bar fill: oxblood #7A1A20 (was green `(0.45,0.85,0.55)`); track: v2 `line` #33161A.
- Hand-debug line: v2 `textDim` #8F8384 slate grey (was flat grey `(0.78,0.78,0.78)`).
- Link/connection-status text: **exactly one green/amber/red family**, switched at render time by
  `LiveClient.ConnectionState` (`Connected`=green, `Connecting`/`Reconnecting`/`Discovering`=amber,
  `Disconnected`=red/crimson) instead of the old static cyan-blue `(0.6,0.85,1)`.

Both files edited via the Edit tool (game/** is file-level text, no MCP needed to write them); recompile
and EditMode/PlayMode verification below are pending the MCP reconnect.
