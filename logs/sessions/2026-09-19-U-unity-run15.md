### Opus-flagged bug fix (interleaved, done immediately per coordinator message)
Opus reported: real Link session `c93ae4fa` trial 3 went `target_shown` -> `contact` (1.3 ms later) with NO
`movement_onset`, because `OrchardReachModule.Tick`'s grasp branch accepts state `TargetShown` directly, and
if `MovementOnsetGate` legitimately returns false (hand hadn't moved by the wrist-displacement threshold —
because it was already at the fruit) while `GraspProximityGate` returns true, contact/grasp fires having
skipped the onset transition entirely. Analytics gates all 12 trial metrics on `t_movement_onset`, so that
real, successful trial got all-null metrics.
- **Fix** (`game/Assets/Games/OrchardReach/Runtime/OrchardReachModule.cs`, `Tick`): when the grasp/contact
  condition is met while still in `TargetShown`, force `_trial.OnMovementOnset(nowMs)` first (same `nowMs` —
  an honest 0 ms onset-to-contact time, not a synthesized delay), unconditionally, before emitting
  contact/grasp. Guarantees `movement_onset` always precedes `contact` in the recorded stream.
- **New EditMode test** (`game/Assets/Games/OrchardReach/Tests/Editor/OrchardReachModuleTests.cs`):
  `HandAlreadyOverTargetAtTargetShown_StillEmitsMovementOnsetBeforeContact` — sets `MovementOnsetGate = _ =>
  false`, `GraspProximityGate = _ => true`, ticks once, asserts both events exist and onset's index precedes
  contact's index in the event list. NOT YET RUN (bridge down at time of writing — see below); will run with
  the rest of the EditMode suite as soon as it reconnects.
- Also fixed a latent bug found while touching this code: `ConfirmPlacedInBasket`'s and `EmitSignal`'s outcome
  string conversion used `outcome.ToString().ToLowerInvariant()`, which cannot produce the schema's snake_case
  `"wrong_target"` for the new `TrialOutcome.WrongTarget` (added this run for stage D). Centralised into a new
  `TrialOutcomeExtensions.ToSchemaString()` extension (`TrialStateMachine.cs`) used by both call sites.
