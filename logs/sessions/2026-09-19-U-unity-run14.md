Root problem found by reading the existing code (not guessed): the demo path already had a "settle" glide
from `AboveBasketPoint()` to `InsideBasketPoint()`, but it was a **plain 250 ms linear `Vector3.Lerp`, no
bounce, no easing** — and the **real-hands release path never used it at all**: on release it did
`if (over) _fruitInstance.transform.position = InsideBasketPoint();` — an instant teleport, which is exactly
the user's #1 complaint.

Fix, shared by both hand sources:
- New `StartBasketDrop(Vector3 fromWorld)` — unparents the fruit and arms a drop from wherever it actually was.
- New `TickBasketDrop()` — called unconditionally every `Update()` frame (not just in the demo's switch
  block), so both real-hands and demo releases animate the same way. Horizontal position eases to the
  basket center slightly ahead of the vertical; vertical falls with `t*t` (ease-in, gravity-like) down to
  `InsideBasketPoint()`, then a small `BounceEaseOut` overshoot (~3 cm × fruitScale, decaying to 0 by t=1)
  reads as a settle-bounce, not a bouncy ball. Duration raised from 250 ms → **400 ms** (spec asked for
  0.3–0.5 s).
- `TickRealHands`'s release branch now calls `StartBasketDrop(_fruitInstance.transform.position)` instead of
  teleporting to `InsideBasketPoint()`.
- Demo's `DriveDemoHandAndFruit` release branch calls the same `StartBasketDrop(releaseTarget)` instead of
  its own linear-Lerp settle block (removed).
- `BasketTrigger.OnTriggerEnter` (unchanged) is still what actually fires `placed` — it now fires while the
  fruit is genuinely moving through the trigger volume during the fall, not at a scripted instant, so
  "placed" timing is a consequence of the visible fall, not decoupled from it. Kept `_settling`/`_settleStartMs`
  reset on both `OnFruitEnteredBasket` and on the next trial's `HandleTrialEvent` reset block (both places
  that already reset `_settleStartMs` now also reset the new `_settling` flag) so a next-trial race can't
  strand a fruit mid-drop.
- `AboveBasketPoint()`/`InsideBasketPoint()`/`BasketBounds()`/`FruitOverBasket()` untouched — placement
  bounds semantics (measured collider, not a hand-typed constant) preserved per CONTEXT.md history.
