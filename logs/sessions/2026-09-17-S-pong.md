## Key Implementation Details

### Ping/Pong Protocol Flow
1. **Hub initiates ping:**
   - Sends ping message with `echo_ts_ms` (current timestamp)
   - Records timestamp in `pending_pings[echo_ts_ms]`

2. **Headset receives and responds:**
   - Validates ping message against schema
   - Extracts `echo_ts_ms` from payload
   - Builds pong message with same `echo_ts_ms`
   - Sends pong back to hub

3. **Hub measures RTT:**
   - Receives pong with matching `echo_ts_ms`
   - Looks up original send timestamp in `pending_pings`
   - Calculates RTT = recv_ts - sent_ts
   - Records in `rtt_samples[]`

4. **Optional: Headset initiates ping**
   - Headset's `measure_latency()` sends pings every 1 second (not started in e2e)
   - Headset records RTT on pong receipt
   - Useful for bidirectional latency measurement

### Schema Validation
- Both ping and pong messages pass full schema validation
- `echo_ts_ms` field is required in payload for both message types
- Validation performed on send (hub) and receive (headset)

### RTT Statistics
- All RTT samples collected in milliseconds
- Statistics computed on-demand: p50 (median), p95 (95th percentile), max
- Both hub and headset track independently (optional for headset if not sending pings)
