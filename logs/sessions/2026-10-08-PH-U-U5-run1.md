### Design notes
- **One run per scene instance.** The U4 panels' `Build()` is not idempotent (children are added again), so presenters are bound once, at the first `StartNewSession` (params are then known from assign_program). A second run (`next_person`, or `start` after a finished run) = `OpusSessionRunner` sets `ProgramHandoff.PendingProgram` (same patient + prescription), the host reloads the scene and the new instance auto-starts (`ProgramHandoff.PendingAutoStartReason`). Calibration comes first, so this is the "reset to Calibrate" path; U6 can time it (target < 10 s).
- **Clock**: a fresh `SessionClock` per run (t = 0 at start, like Orchard); the two `SleeveSensorClient`s are created with that clock at run start over the persistent transports (their clock-offset estimators cannot survive a clock reset).
- **haptic_cue events**: HapticClient raises a record at send and again at ack; the adapter writes ONE event per cue when the outcome is known (analytics counts delivered / scheduled per condition): ack -> delivered true with ack_latency_ms; drop / rejection / no ack after 1.5 s -> delivered false + reason. `trial` = condition index at send time.
- **Live status** (2 Hz, runner): generic fields + `game_id`, `game_state` {phase, condition, remaining_s, nodes{haptic{connected}, bio{connected, emg_level}}} (haptic/bio `connected` = node stream alive in a run, discovery latch before a run; emg_level null unless Node B is connected AND an EMG calibration exists), `trace` {emg_env[], accel_mag[], t0_ms, fs_hz 20} built from 50 ms bins of the node rings, <= 100 per array, empty array when a stream is silent.
- **metrics_tick** (`window_trials` = condition index + 1; metric id -> {value, unit, quality} plus a `condition` label entry): after the post probe (drift), after the threat response (flinch), after the questionnaire (ownership/control), only values known.
- **Commands**, all acked: start (idempotent) / pause / resume / stop (core), recenter (PH: ack ok=false "recenter is not used by this game"), phase_next + abort_phase (ignored with ack ok when no run is active; abort also stops the sleeve), set_condition_order (needs params.condition_order; accepted before the first induction of an active run or kept for the next run; once induction started ack ok=false), next_person (ends a run, reloads). Each also writes a `command_received` event while a run exists.
- **Missing peers**: no Node A -> every stroke is a `haptic_cue` delivered=false (reason no_device) and the U4 HUD chip "Sleeve offline" is the presenter's; no Node B -> EMG null (collector flags), `emg_env` empty, `bio.connected` false; no hub -> the runner records locally and uploads when it reconnects (unchanged logic, sens files included).
- **Stop-safety**: `OnDisable`, `OnApplicationQuit`, `OnApplicationPause(true)`, `OnDestroy`, `EndSession`, `PauseSession`, `abort_phase` -> `HapticClient.Stop()` (cancels queued strokes, sends stop) and `SendDisplay("IDLE")`; keepalives stop at the end of a run.
- **Hands**: headset -> `MetaHandSource` over `OVRHandDataSourceLeft/Right` and the Hmd on `OVRHmd`; no headset -> `ScriptedHands` (+ `PhantomAutoParticipant` when `scriptedParticipantWithoutHeadset`). Kinematics of ALL joints of both hands via `KinematicsSampler` at <= 72 Hz in scene (calibration) space, tracking_lost/regained events; sensors via `SensorRecorder` (+ `motor_excl` from the cue windows); measured tracking rate (headset only) goes into session.json.

## Open issues / requests
1. **CROSS-TRACK (SDK, U1): `LiveClient` hub port is the const 8787** (ws URL and HTTP uploads). The L3 harness passes `OPUS_PH_HUB=host:port` with arbitrary ports. The controller logs a warning and uses the host only; PH_FullRun asserts the hub is on 8787. Request: optional `hubPort` constructor argument (default 8787).
2. **CROSS-TRACK (SDK, U1): `UdpHapticTransport.ReceiveLoopAsync` breaks on any `SocketException`.** On Windows a UDP send to a node that is not up yet / has just lost power gives an ICMP "port unreachable" and a WSAECONNRESET (10054) on the next receive, which ends the loop for good (S2 saw the same in live_plot). Request: ignore 10054 and continue. Until then a node power-cycle mid-run can silence a client until the scene is reloaded.
3. **After `pause` + `resume` the stroke plan is gone** (`HapticClient.Stop` cancels queued strokes, and `StrokeDriver` scheduled them all at induction start). Needs a U3 reschedule-on-resume (not my files). Operator pause during induction therefore ends the touch for that induction.
4. Presenters are bound with the params of the first run (arm geometry is rebuilt if forearm / motor params change between runs in the same scene, but `follow_during_induction` etc. are read live).
5. `next_person` and `start` after a finished PH run reload the scene (~1-3 s, node re-latch <= 1 s after). Not timed.
6. `PhantomHandUiPresenter` / `ArmThreatPresenter` are called by type (`Bind` / `Tick` / `CalibrationTarget()` / public `anchors`, `arm`); a rename by the UI/3D builders breaks the Shell compile.
7. EMG `emg_level` stays null until an EMG calibration exists (agency, stretch).
8. `PhantomHandSettings.autoStartOnHeadset` is off by default: a headset without the app starts by the both-hands pinch (1.5 s) or the clinician's Start.
9. The test agent needs: Unity lock, `sim/live/.venv` (python), analytics venv, no `adb forward` on 8787, nothing on 12100-12103. Command: `-runTests -testPlatform PlayMode -testFilter PH_FullRun`; EditMode filter `Opus.Shell.Tests` (25 tests in PhantomHandShellTests).
