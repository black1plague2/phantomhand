## SPEC QUESTIONS (conservative choice made; Opus please confirm or override)
1. Event field placement: all new event fields live in `data` (consistent with `haptic_cue.data.cue`); `trial` = condition index (0 = first condition run), pre-condition events use trial null. `data` is REQUIRED, with the stated keys, for the new types.
2. Phase names (not in spec): calibrate, probe_pre, induction, agency, threat, probe_post, questionnaire, dissolve, reveal, witness, done (free string in schema, listed as examples). `condition` values are lowercase `sync` / `async`, null outside the conditions.
3. drift_probe: `drift_cm` positive = toward the virtual hand (virtual arm sits at negative x); perceived_x / actual_x in metres, calibration space. The spec gave no units.
4. witness_summary: `data` needs at least one of `sync` / `async` (free objects), optional `condition_order`.
5. threat_response.quality is ok|degraded|missing (spec 8 wording); its numbers are nullable. stroke cue_*_send_ms and timing_err_ms are nullable (gated or haptics off); timing_err_ms = actual send minus intended send, signed.
6. sens_###.json is COLUMNAR like kin: `emg_env{device_id,t_ms[],value[]}`, `imu{device_id,t_ms[],ax..gz[]}`; device_id is one string per stream; optional `rate_hz`, `unit`, `motor_excl[]`. `source` enum udp|synthetic|replay. t_ms is SESSION ms. Envelope field is `sensor_chunks`.
7. sensor_chunk: 1-10 envelope values; `sample_rate_hz` any 1-1000 (not const 100) so a firmware variant is not rejected.
8. metrics `embodiment`: `{condition_order, sync, async, sync_minus_async}`, each a map of metric id to value; `stroke_timing_err_ms` is `{mean, p95}` of values, not a single value. The maps are open (extra ids allowed).
9. set_condition_order params: required `{"condition_order": "sync_first"|"async_first"}`; phase_next, abort_phase, next_person take no params.
10. live trace: arrays at most 100 samples, fs_hz const 20; game_state requires phase, condition, remaining_s, nodes{haptic.connected, bio.connected (+emg_level)}.
11. Manifest: `stimulated_side` enum ["right"] has one value, so the app dynamic form must handle a one-option segmented/enum. Integer params: induction_s, all *_ms, self_touch_s, breath_replay_lag_s; number params: cm, Hz, intensity, thresholds. `events` also lists generic lifecycle events (session_start/end, block_start/end, pause, resume, tracking_lost/regained). bodyRegions [forearm, hand, cognition]; sdkVersion ^0.1.0 as Orchard. Orchard's manifest is CRLF, the new ones are LF.
12. The internal v1 `cue` message enum did NOT get "stroke" (strokes use only the device-level command).
13. status `subscribers` capped 0-3 in the schema (device max).
